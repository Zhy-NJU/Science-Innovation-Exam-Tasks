# Final independent verification

The frozen `reaction_barrier` package passes both the official bundled contract
checker and the real public framework's `TaskPackage.load`. The final package
contains **24 regular files, 12,121,884 bytes**, with no `__pycache__`, `.pyc`,
links, special files or undeclared input. Per-file sizes and SHA-256 hashes are
recorded in `final_package_manifest.json`.

## Scientific and interface checks

The full independent suite passed **33/33 checks**. It covers known numerical
fixtures, negative and extreme finite predictions, strict complete-ID parsing,
bounded artifacts and unsafe ZIP rejection, persistent 20-call development
budgets, non-consuming rejections, corrupted-state failure, actual framework
request-ID retry and terminal behavior, response disclosure boundaries, and
full exported-data field/geometry/split/reference checks.

That historical report inspected 26 files. Since then, only `instruction.json`,
`meta.json` and `input/README.md` changed; two generated bytecode files were
removed. The final audit verifies that **all verifier source, protocol and
scientific data hashes remain identical** to those tested by the 33-check
suite. The final official schema and structure checks were run after those
metadata changes. The historical 26-file report is not the current manifest.

`746dc2d7c0c7c4b979c5c7371edf2e0ad15c7607`; the task contract is pinned at

  with the real SDK. The container service and Linux ownership setup were
  explicit test doubles; these are controller unit tests.
- The 33-check task suite uses real SDK subprocesses. Framework Actions uses
  an explicitly local subprocess adapter.
- A separate known-value smoke passed with system Python 3.9; the main audit
  used Python 3.11.
- **No Docker/container end-to-end run or complete research-agent run was
  performed.** These checks do not establish OS isolation or runtime resource
  enforcement.

The baseline was constructed by a local harness that read hidden development
labels for the three predeclared aggregate evaluations. Subsequent real-SDK
validation-entry replay reproduced those three aggregates and the same model
selection. It is not evidence that the original fitting and selection ran
inside the isolated benchmark action interface. Test predictions were frozen
before the independent test-label arithmetic audit.

## Repeating the final audit

From the reaction build root, with the public framework source and contract
snapshot present, use a Python installation with `jsonschema`:

```sh
python -B build/tests/final_contract_audit.py \
  --package task_package \
  --framework official-framework \
  --contract ../official-contract-2026-10-29/contributor/build-afe-task-package \
  --results build/official_verifier_results \
  --prior-report build/tests/independent_package_tests.json \
  --output build/tests
```

Adapt only these paths when using a different checkout layout. The final
repeat-score check requires the original four-file baseline/bottom submissions
and trusted three-round SDK context; the aggregate JSON evidence alone cannot
reconstruct those artifacts. The script does not create a replacement SDK or
write to the task package. See `final_contract_audit.json` for exact hashes,
scope and the relation to the historical 33-check report.
